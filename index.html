Research

Soil moisture data fusion and hybrid nowcasting

Sponsored research for Aperture Space, Inc.

In a benchmark on 340 U.S. stations, my model’s median error was 0.0421 m³/m³. SMAP L4 v007 scored 0.0540 on the same observations, so my error was 22% lower. Both used the same de-biasing and station-held-out cross-validation.

How it works
How big is the error, compared with real sensors?
What went into the dataset
3.06M station-days of ground observations from 1,599 stations in 56 networks (ISMN). The baseline started with 120 Oklahoma Mesonet stations and scaled to 1,599 ISMN stations worldwide.
ERA5-Land and CHIRPS weather, plus IMERG and PRISM precipitation.
SoilGrids soil properties, SRTM terrain, and ESA WorldCover land cover.
1.44M Sentinel-1 radar acquisitions, Sentinel-2 optical indices, and MODIS land-surface temperature.
What the experiments showed
How I built it
  • Method. A gradient-boosted model estimates today’s moisture, and temporal residual corrections adjust it. A 90-day weather and satellite CNN extension is in multi-seed evaluation.
  • Skill metric. 1 − A/B compares model error (A) with a seasonal-average baseline (B) on the same observations. It shows what the model learns beyond the seasonal cycle.
  • Free inputs only. The baseline is a free-data reference for a satellite-sensor startup: Sentinel-1, Sentinel-2, ERA5-Land, and CHIRPS through Google Earth Engine, with station-wise splits.
  • Careful joins. Dates are corrected to local time, only past weather is used, and every satellite acquisition is kept.

How I built it
  • Batch jobs leave the web request. Redis-brokered Celery workers run them and PostgreSQL keeps the job state. A failed callback is retried on its own, so the translation never runs twice.
  • Two engines. OPUS-MT models and one shared 600M-parameter NLLB model behind a lazy-loading, LRU-cached model manager. GPU runs use fp16 with warmup.
  • Safe for many users. Hashed API keys and JWT, per-key sliding-window rate limits, and monthly quotas. Text and sentence caches in Redis avoid repeated inference.
  • Ready to run, and honest about scope. Prometheus metrics, liveness and readiness probes, and request-ID logs. The free public demo (GitHub Pages and a Hugging Face Space on ZeroGPU) uses a reduced path without PostgreSQL, Redis, or Celery, while the full stack runs all of them. Backend tests stub the heavy ML libraries so CI stays fast.

Live demoSource code

An interactive 36-country map of each country’s top news and internet culture, explained for outsiders by a language model.

The 36 countries
How the weekly refresh works
Google News RSS for news. For culture, Reddit country and culture subreddits and YouTube regional trending, because Google Trends and Wikipedia pageviews returned news, not culture. Reddit’s JSON endpoints return 403 but its RSS feeds work, behind a global throttle, and CI uses read-only OAuth. If a source fails or is blocked, as YouTube trending is in China, the country falls back to the others.
Rule-based filters drop, penalize, or boost each candidate (routine politics, sports scores, press releases, sticky posts). Every candidate keeps a diagnostic that shows why it was kept or buried, and a per-source quota keeps both Reddit and YouTube in each country’s feed.
The language model does only two jobs: the final selection and the cross-cultural explanation.
GitHub Actions refreshes the data every week and redeploys the site. Hovering never calls an API, because the browser only reads static JSON. Cost stays near $0.50 a month, about $6 a year, whatever the traffic.
A 36-country map in vanilla JavaScript and SVG over GeoJSON, with no backend or database. Open the live demo.
How I built it
  • Two pipelines. News and internet culture are separated, because one trending feed was dominated by news. Hard-exclusion rules can be audited.
  • No model calls in the browser. Explanations are generated in batch and served as scheduled static JSON. Failed sources have fallbacks, and a pytest suite that needs no network runs on every push.
