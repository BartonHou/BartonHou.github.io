Research

Soil moisture data fusion and hybrid nowcasting

Sponsored research for Aperture Space, Inc.

In a benchmark on 340 U.S. stations, my model’s median error was 0.0421 m³/m³. The NASA SMAP L4 product scored 0.0540 on the same observations, so my error was 22% lower.

  • Built a multi-source geospatial dataset with 3.06M station-days of ground observations from 1,599 stations in 56 networks. I combined it with ERA5-Land and CHIRPS weather, SoilGrids soil properties, SRTM terrain, and ESA WorldCover land cover.
  • Aligned 1.44M Sentinel-1 radar images, Sentinel-2 optical indices, and MODIS land-surface temperature to each satellite pass. The joins fix local dates, use only past weather, and keep every acquisition.
  • Designed a hybrid framework. A gradient-boosted model estimates the current moisture, and temporal residual corrections then adjust it. I also built a 90-day weather and satellite CNN extension with nested station holdouts and validation-selected fusion weights. Multi-seed evaluation is in progress.
  • Ran the benchmark with PRISM-enhanced LightGBM on 106,584 matched observations, using station-held-out cross-validation and identical de-biasing for both models.
  • Defined a skill metric, 1 − A/B, that compares model error (A) with a seasonal-average baseline (B) on the same observations. It shows how much the model learns beyond the seasonal cycle.

Adaptive time-series tokenization and forecasting

Research in progress.

  • Extended the Chronos forecasting model with adaptive quantization. Per-bucket error and uncertainty scores guide where token boundaries move, and an online controller splits and merges tokens while keeping the vocabulary size fixed.
  • Remapped embeddings by token count and reset optimizer state when boundaries change, including the shared input and output embeddings. Unit tests cover vocabulary size, remapping, and updates.
  • Built Chronos and PatchTST training and evaluation paths with held-out series tails and rolling-origin backtests. Implemented MASE and WQL metrics, with tests that check training and evaluation targets never overlap.

Systems projects

Multilingual translation service

FastAPI, Celery, Redis, PostgreSQL, Docker, PyTorch.

Live demoSource code
  • Designed three ways to translate: a direct request, a sentence-by-sentence stream, and an asynchronous job, all sharing the same inference code.
  • Moved batch and file jobs out of the web request into Celery workers backed by Redis and PostgreSQL. Signed callbacks are retried on their own, so a failed callback never re-runs the translation.
  • Covers 9 languages with OPUS-MT models and one shared 600M-parameter NLLB model. Pairs without a direct model go through English. Models load on demand, the least recently used one is evicted, and GPU runs use fp16 with warmup.
  • Shared sentence caches across all paths. Added glossary protection, language detection, per-key quotas, and sliding-window rate limits.
